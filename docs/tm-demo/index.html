대외활동 포스터, 어느 분야일까?

대외활동 플랫폼에 올라오는 포스터를 사람이 일일이 분야별로 나누는 일을 Teachable Machine 이미지 모델로 돕고자 했다. 포스터 180장으로 7개 분야 분류 모델을 학습하고, 학습에 쓰지 않은 포스터로 한 번만 평가했다. 그 결과를 분석해 모델의 약점(글자를 읽지 못함)을 찾아냈고, 이를 보완하는 확장까지 진행했다.

라이브 데모 — 모델이 실제로 판단하는 모습

포스터를 올리면 학습한 Teachable Machine 모델이 7개 분야의 확률을 바로 계산한다. 이 데모는 1차 Teachable Machine 단독 결과만 보여 준다.

이미지는 이 브라우저 안에서만 분석되고 어디에도 전송되지 않습니다.

모델을 불러오는 중…

바로 체험하기 — 직접 만든 가상의 예시 포스터 (실제 행사가 아닙니다. 실제 포스터는 저작권 때문에 싣지 않았습니다)

판정 규칙 보기

1위 점수가 0.80 이상이고 1·2위 차이가 0.20 이상이면 자동 제안, 아니면 관리자 검토 필요로 둔다. 모델이 확신하지 못하는 포스터는 사람이 확인하게 하려는 설계다.

"판단 근거 보기"는 어떻게 계산하나요?

모델이 보는 224px 이미지를 7×7 칸으로 나누고, 한 칸씩 회색으로 가린 뒤 다시 분류한다(가림 실험, occlusion). 어떤 칸을 가렸을 때 1위 분야의 점수가 많이 떨어지면, 모델이 그 부분을 근거로 판단했다는 뜻이다. 빨갛게 진할수록 중요한 칸이다. Teachable Machine 모델만으로 49번 추론해서 계산하며, 이미지는 브라우저 밖으로 나가지 않는다.

데이터셋 설계

공개된 대외활동·동아리 포스터 180장을 직접 모아 라벨을 붙였다. 학습 144장, 평가 35장이고, 분야 밖 포스터 1장은 평가에서 뺐다.

라벨분야범위학습평가비율

분류 구성이 바뀐 과정

  1. pilot-4-v1 IT·데이터, 경영·기획, 디자인·미디어, 사회·환경 4개로 시작했다.
  2. pilot-6-v1 팀 검토에서 법·정책과 교내 행정 공지를 추가했다. 공학은 IT에 합쳐 IT·공학으로 바꾸고, 포럼·컨퍼런스 같은 단순 참관 행사도 주제가 가장 가까운 분야로 넣었다.
  3. pilot-7-v1 운동·취미·문화 동아리와 공연·축제가 많아 취미·문화생활을 추가했다. 순수 미술·캘리그라피·문학 공모는 디자인·예술·미디어로 넣었다. 지금 모델이 이 구성이다.

라벨 규칙과 데이터 원칙

  • 참가자가 주로 하는 일·제출하는 것으로 분야를 정한다 (예: 브랜드 서포터즈 → 경영·기획, 봉사 → 사회·환경).
  • 단순 참관 행사도 주제가 가장 가까운 분야로 넣는다.
  • 학교 부서가 재학생에게 안내하는 공지는 교내 행정 공지로 분리한다.
  • 분야가 애매하면 팀 검토 후 정하거나 뺀다(중복·부적합 5장 제외).
  • 같은 기관의 같은 시리즈 포스터는 학습·평가 중 한쪽에만 둔다.
  • 사진 복제·증강으로 개수를 부풀리지 않는다.
  • 검증용(dev) 세트 없이 한 번 학습, 한 번 평가한다. 평가 결과를 보고 다시 학습하지 않는다.
  • 포스터 원본은 저작권 때문에 공개 저장소에 올리지 않는다.

학습 설정

Teachable Machine의 표준 이미지 모델을 기본 설정 그대로 한 번 학습했다. 설정을 평가 결과에 맞춰 바꾸지 않아서 결과를 그대로 믿을 수 있다.

학습 이미지와 서비스·데모가 같은 전처리(pad-square-v1)를 거치게 해서, 학습할 때 본 모습과 실제로 판단할 때 보는 모습이 같도록 했다.

왜 흰 여백(pad)으로 맞췄나

모델 입력은 정사각형인데 대외활동 포스터는 대부분 세로로 길다. 가운데만 잘라 내면 제목과 일정이 있는 위아래가 사라지고, 늘리면 그림이 찌그러진다. 그래서 포스터 전체가 보이도록 여백을 붙였고, 학습용 이미지와 서비스·데모가 똑같은 전처리를 쓴다.

오류 분석 — TM의 약점 찾기

틀린 사례를 묶어 보면 우연이 아니라 일정한 패턴이 있었다. 이 패턴이 다음 단계(보완)의 근거가 됐다.

가장 많이 헷갈린 분야 쌍

    처음 보는 기관에서 더 약하다

    결론: 모델은 '그림체'를 보고 판단한다

    1

    분야 정보는 글자에 있다

    포스터의 분야는 "해커톤", "봉사", "공모전 주제" 같은 글자로 드러난다. 그런데 224px로 줄이면 작은 글자는 거의 사라지고, 모델에는 색·구도·그림체만 남는다. 데모의 전처리 이미지에서 직접 확인할 수 있다.

    2

    기관의 디자인 스타일을 외운다

    학습에 없던 기관의 포스터에서 정확도가 크게 떨어졌다. 분야보다 기관별 디자인을 일부 외웠다는 신호다.

    3

    분야마다 표본이 적다

    분야당 학습 이미지가 적어 그림체가 비슷한 분야(일러스트가 많은 공모전과 캠페인 등)를 구분할 근거가 부족했다.

    확장

    약점 보완 — 모델이 못 보는 글자를 더하다

    오류 분석의 결론(분야 정보는 글자에 있다)에서 출발해, Teachable Machine 결과는 그대로 두고 포스터 글자를 읽는 두 신호를 더했다. 모든 처리는 브라우저 안에서 무료 도구로 돌아간다.

    방식정확도macro-F1자동 제안 중 정답처음 보는 기관
      공정성 원칙

      키워드 사전, 분야 설명문, 결합 비율, 판정 규칙은 모두 학습용 포스터와 라벨 규칙만 보고 만들었고, 평가 포스터를 보기 전에 고정했다. 평가는 같은 test로 한 번만 했다.

      한계와 향후 계획

      • 표본 크기 평가 포스터가 35장이고, 법·정책과 교내 행정 공지는 2장씩이다. 신뢰구간이 넓다(—).
      • 같은 평가 세트 재사용 1차와 보완 평가 모두 같은 test를 썼다. 보완 규칙은 test를 보기 전에 고정해 영향을 줄였다.
      • 장식 글꼴 큰 제목만 있고 글자가 장식적인 포스터는 OCR도 읽지 못해(—장) 모델 결과에만 의존한다.
      • 이미지 축소 방식에 민감하다 큰 포스터를 224px로 줄일 때 브라우저·운영체제마다 축소 알고리즘이 달라 점수가 바뀔 수 있다. 다른 환경(Linux의 Chromium)에서 test 포스터 6장을 돌려 보니 3장의 1위 분야가 평가 때와 달랐다. 평가는 Windows의 Chrome에서 했고, 이 데모 페이지를 같은 환경(Windows Chrome)에서 열어 같은 test 6장을 다시 돌렸을 때는 6장 모두 평가 때와 1위가 같았다. 그래서 시연은 Windows Chrome에서 한다. 다음 버전에서는 축소 단계를 고정한 전처리(v2)로 다시 학습해 환경 차이를 없앤다.
      • 임베딩의 효과가 작았다 분야 사이 점수가 고르게 퍼져 결합에서 힘을 쓰지 못했다.
      • 향후 분야별 포스터를 더 모아 새 평가 세트로 다시 학습하고, 결합 비율은 새 데이터로 검증한다. 외부 AI(LLM)는 비용·외부 전송·재현성 문제로 후보로만 둔다.

      재현 방법과 링크

      • Teachable Machine 모델 공유 링크 — 같은 데이터·기본 설정으로 다시 학습해 업로드한 공유용 모델. 평가 수치는 원래 모델 기준
      • GitHub 저장소 (서비스 전체 코드)
      • 실험 기록 (결과 파일·라벨 목록·키워드 사전)
      • Teachable Machine 연동 설계 문서
